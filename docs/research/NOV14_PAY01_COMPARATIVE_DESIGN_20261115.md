## 1. 현행 소스에서 확인된 계산 경로

1. [server-sync-sheet/index.ts](../../supabase/functions/server-sync-sheet/index.ts)의 `sourceFor(ym,storeId)`가 `sheet_server_payroll_source` RPC를 지점·월로 조회한다. 지점별 `payroll_weekly_approvals`, `employment_periods`, `employment_contract_workdays`, `work_schedules`를 추가로 조회해 서버 급여 엔진에 입력한다. 복구/정정원본과 지점 PK를 출처로 유지해야 한다.
2. [engine.mjs](../../supabase/functions/server-sync-sheet/engine.mjs) `createPayrollEngine().computeMonthPayroll(ym)`는 직원별 HOURLY/MONTHLY 계약, 근로시간/휴게, 대체근로, 주휴/관리자 주차 조정, 재직기간의 기본급 및 금액을 계산한다. HOURLY의 계약 시간창과 실제 타각 교집합은 실구현·검증 경계를 유지한다. 실제 근무시간 원본은 수정하지 않는다.
3. `calcPayroll`의 비계약/구형 경로에는 `tax_rate` 미지정 시 **0.033** 기본값과 `gross × (1-rate)` 단순 세후 계산이 있다. MONTHLY도 `tax_treatment=BUSINESS_INCOME`인 계약에 별도 0.033 적용 경로가 있다. **이는 2026 근로소득 간이세액표·4대보험 개인별 자격/기준소득월액을 계산하는 대체 수단이 아니다.** PAY-02에서는 기존 단순 `net`을 법정 공제 확정액으로 그대로 복제하지 않는다.
4. [payroll_policy.mjs](../../supabase/functions/server-sync-sheet/payroll_policy.mjs)는 주휴 소정근무일·근로시간·미종결/대타 여부와 승인 사유를 분리한다. 승인 근거 없이 주휴의 미산출 항목을 0원으로 확정하지 않는다.

## 2. 입력과 출력 데이터 계약 (설계)

| 내부 정본 / 가상 Excel 헤더 | 검증 | 출력 |
|---|---|---|
| store_id, 월(YYYY-MM), 직원 ID | 지점·월 범위·직원 PK 결속, 중복/타지점 차단 | 지점별 월 요약 |
| 근태 이벤트·정정·원본 이벤트 ID | 원본 불변, 타각쌍·휴게·야간·시간대/자정·정정 상태 | 직원별 검증된 지급 시간 |
| 유효 계약 ID/버전, HOURLY/MONTHLY, 시급/월급, 적용일 | 월 중 계약 변경, 재입퇴사, 근로계약 시간창, 기초자료 누락 차단 | 기본급·주휴·수당·조정 사유 |
| 주휴 승인·월 마감 스냅샷·결정자/시각 | 미산출≠0원, 승인 전 금액 확정 방지, 반복 계산 동일성 | 확정 세전 지급액 |
| 지급월, 근로소득/사업소득 과세 유형, 공제/보험 적용 대상 및 기준소득월액 | 유형 미분류·보험 자격 미확정은 금액 계산 보류 | 국민연금·건강·장기요양·고용·소득세·지방소득세 항목별 금액 |
| 간이세액표 버전·부양가족·원천징수 비율·공제 기준월 | 국세청 공식 표 및 유효기간 기준, 임의 세율 불가 | 원천세·실지급액 |
| 명세서 버전·직원 ID·해시·승인 상태 | 직원별 파일명 충돌·중복발급·타점 누락/혼입 차단 | 직원별 PDF 및 월별 집계 |

**회계상 원칙:** `gross = 근로계약에 맞는 기본급 + 검증된 주휴/수당 + 승인된 조정`. `deduction = 자격·신고 기준월이 확정된 직원별 보험료 + 간이세액표에 따른 원천세 + 기타 적법한 확정 공제`. `net = gross - deduction`. 금액 단위/절사/상하한/기준월은 항목별 공식 규정과 지급시점의 실제 사업장 설정으로 결정하고, 한 번 계산한 결과에는 세율/표 버전과 원천기록 해시를 보존한다. 세전 급여에 3.3%를 일괄 곱하지 않는다.

## 5. 합성 검증 시나리오와 PAY-02/03 수용 경계

- **C1 원본↔직원 매핑:** `(store_id, ym, employee_id)` 유일. 같은 이름/한글 이름 변화가 있어도 직원 ID 기준으로 연결; 타지점/중복/누락은 계산 중지.
- **C2 HOURLY 계약 교집합:** 계약 08:00~10:00, 실제 07:50~10:00, 시급 12,000원 → 인정 120분·기본급 24,000원(주휴/야간/법정공제 별도). 실제 08:15~10:00이면 105분·21,000원. 타각 원본을 고치거나 조기출근 무급을 일괄 법적 확정하는 처리는 이 테스트에서 하지 않는다.
- **C3 MONTHLY:** 계약 월급 2,500,000원, 월 전체 정상 재직→비공제 세전 기본급 2,500,000원. 중도 입퇴사는 계약 유효기간과 재직기간의 일수 교집합을 별도 검산. 출퇴근 건수 0을 곧바로 월급 0으로 처리하지 않음.
- **C4 주휴:** 실제 엔진 `assessWeeklyRest`의 주 900분·계약일 근무·미종결/대타/퇴사 예외·월말 주 소속 검사를 재사용. 계산 자료가 없으면 UNKNOWN, 근거 있는 산출 0원만 0원 처리.
- **C5 공제/세액:** 근로소득인데 3.3% 고정세율 입력되면 `NEEDS_TAX_CLASSIFICATION`으로 보류; 연도·자격/기준월 미확정 시 `NEEDS_RATE_SNAPSHOT`; 공식 표와 별도 기대값 비교 후에만 실제 사용.
- **C6 명세서:** 직원당 정확히 PDF 1개, 월/지점/직원 해시로 중복 재실행 방지, 0명/파일경로 충돌/시스템 저장 실패/합계 불일치가 있으면 배치 실패. 민감한 파일은 로그·PR·공개 저장소에 업로드하지 않는다.
- **C7 이메일(후속 PAY-03):** 가상 메일함 점주 1곳·직원 2명, 다른 지점 1명의 첨부가 섞이는지 음성 테스트. 운영 직원·점주에게는 승인 전 발송 금지.
- **C8 결정 불확실성:** Excel 실제 원본/버튼 위치·폼/셀 범위, 점주가 원하는 저장 UX, 보험 공제에 쓰는 실제 신고자료, 원천세 표, 개인별 보호/전달 방식이 없으면 출력 형식·실급여를 ACCEPTED로 올리지 않는다.

### 다음 단계(이 작업의 미완료와 혼동 금지)
