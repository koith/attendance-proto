# 대표 초대와 인증 후 개통

본사가 지점 개통 조건을 확인하고 대표 초대 확인창에서 개통까지 승인하면, 수신자는 이메일 인증과 개인 비밀번호 설정을 마친 후 바로 해당 지점 관리자 화면으로 이동한다. 대표 등록 뒤 본사에 같은 승인을 한 번 더 요청하지 않는다.

초대 전과 수락 시점에 모두 실제 지점 확인 이력, 샘플 직원 제외, 준비 상태와 유효한 본사 승인자를 확인한다. 대표 등록과 READY 전환은 같은 PostgreSQL 트랜잭션이다. 조건이 바뀌면 역할 등록과 개통을 함께 취소하고 기존 초대는 보존한다. Auth에 저장된 비밀번호를 되돌리거나 관리자에게 보여주지 않는다.

신규 승인에만 pending claim의 `auto_open_after_accept`가 기록된다. 기존 claim의 기본값은 false이며 소급 개통하지 않는다. 필드는 익명·수신자가 쓸 수 없는 기존 service-only 테이블에 있다. 신규 service-only 오버로드는 기존 발급 함수의 본사/계정/지점 검증을 먼저 실행한다. 보조 관리자와 다른 지점은 이 승인으로 개통되지 않는다.

재발송은 유효한 기존 claim의 사용자·역할·지점·승인 여부·기한을 그대로 사용한다. 새 승인을 만들거나 기한을 연장하지 않는다. 취소 또는 만료된 초대는 본사가 새 초대로 승인해야 한다. 응답 유실 후 완료 재시도는 현재 본인의 비밀번호와 이미 존재하는 대표/관리자 연결만 확인하며 권한을 다시 주거나 지점을 재개통하지 않는다.

운영 배포는 격리 PostgreSQL 검증 후 진행한다. 마이그레이션은 기존 지점이나 계정을 활성화하지 않는다. Edge 배포본과 정적 클라이언트가 같은 코드인지 확인하고 운영 Sheets를 갱신하는 일반 Pages 경로를 사용하지 않는다. 실패 시 이전 Edge/클라이언트와 완료 함수로 되돌릴 수 있으며 계정·근태·급여·레시피나 새로 생성된 운영 기록을 삭제하지 않는다. 미완료 초대의 개통 승인을 취소할 때는 해당 본사 승인 범위와 대상만 확인해 처리한다.
