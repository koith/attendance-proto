> **상태: 준비 중 / 운영 서비스 변경 없음.** 이 문서는 기술적 관리 절차를 정리하기 위한 것이다. 서비스 종료, 소유권 이전, 계정 이전, 키 교체, 실제 급여·근태 변경을 승인하지 않는다.

> 공개 저장소용 문서이므로 실제 계정 주소, 직원 개인정보, 상세 취약점 재현 절차, 환경 비밀값, DB 백업 URL, 유효 토큰은 기록하지 않는다. 민감한 검증 증거는 접근 제한된 별도 보관소로 분리한다.

## A. 서비스와 데이터 흐름

- 클라이언트: GitHub Pages 정적 웹앱, 모바일 브라우저/웹뷰 및 매장 PC.
- 서버: Supabase Auth, PostgreSQL/RLS/RPC, Supabase Edge Functions.
- DB: 매장, 직원, 출퇴근 이벤트와 정정 이력, 근로계약, 급여 기간·스냅샷, 점포·관리자 멤버십.
- 외부 연동: Edge `server-sync-sheet` → Google Apps Script → Google Sheets `2026 근태`.
- 예약 실행: PostgreSQL pg_cron에 업무 자동화 작업이 존재한다. 작업 목록은 운영 DB에서 조회해 검증하며 여기에는 토큰·요청 헤더를 복사하지 않는다.
- 파일: 별도 비공개 직원 문서 저장소와 공개 썸네일 저장소. DB 백업은 실제 파일의 복구와 별개이며 Storage 객체 복구까지 고려한다.
- 관리자: 본사 관리자, 지점 대표 관리자, 보조 관리자, 직원의 권한을 각 경로에서 점검한다. 겸직이 가능한 기존 계정의 권한을 임의 수정하지 않는다.

## B. 변경 전 선행 조건

1. 최신 `main` SHA, 운영 페이지 리비전, Supabase 실제 Edge 버전과 파일 해시, 운영 DB 함수 정의·권한, 예약 작업 상태를 각각 기록한다.
2. 실제 운영 데이터와 인증정보를 사용하지 않는 **격리 환경**에서 재현·QA를 수행한다. 일시 정지, 백업 삭제, 운영 DB 초기화, 급여 마감, 직원 PIN 입력 공격 실험 금지.
3. 백업의 **실제 존재·최신 시점·보존기간·복원 성공**을 별개로 확인한다. 복구 검증이 없으면 운영 고위험 변경 승인 보류.
4. DB 스키마, 데이터, Supabase Storage 객체, Auth 사용자/인증 설정, Edge Secrets, Apps Script 설정과 Sheets 권한은 서로 다른 복구 대상임을 명시한다.
5. 범위 제한된 변경만 별도 브랜치와 PR로 생성한다. CI/병합/배포/현장 실사용 결과를 별도 증거로 보고한다.
6. 기존 운영 중인 자료를 삭제하거나 마이그레이션을 역으로 적용하지 않는다. 롤백은 먼저 **코드·구성** 중심으로 설계하며, 새로 발생한 출퇴근·급여 기록을 보존한다.

## C. 배포·긴급 복구 절차

**배포 전:** 책임자·승인 기록, 기대 개선점, 영향받는 DB/RPC/화면/API, 호환성, 단계별 변경, 정지 기준, 복구를 사전 점검한다.

**PR 검증:** 최소 권한, 정상 PIN·출퇴근·정정, 근태 조회, 점주/본사/보조관리자 역할 구분, 지점 간 격리, 급여 재계산, Sheet 동기화, 모바일·PC 해상도, 웹뷰로 돌아왔을 때 복구를 확인한다. 합성 데이터 테스트와 실제 iPhone 실기 테스트를 혼동하지 않는다.

**배포 후:** 배포 SHA, 실제 로드되는 파일 버전, Edge 파일 바이트 비교, DB 함수/ACL 재확인, 주요 읽기·정상 서비스 동작, 오류 로그, 동기화 상태를 확인한다. 운영 사용자·직원 데이터는 테스트 용도로 쓰지 않는다.

**이상 발생:** 추가 배포를 보류하고 발견 증거를 보존한다. 사용자 영향 범위를 계산한 후, 새 운영 데이터를 보존하는 방식으로 직전 안정 코드/구성을 복원한다. DB 스냅샷의 무조건 덮어쓰기는 금지한다.

## D. 백업·복구 검증 체크

- [ ] Supabase 대시보드 또는 관리 API에서 백업 **목록·시각·보존기간** 확인
- [ ] DB 논리 백업/물리 백업/PITR 가능 여부·플랜 확인
- [ ] 실제 운영 이력을 변경하지 않는 격리 복구 및 샘플 무결성·건수 점검
- [ ] Storage의 직원 문서 실제 객체 복구 확인 (DB 메타데이터 복원과 구별)
- [ ] Auth 및 권한·Secrets **재구성** 절차 검증(비밀값은 문서에 쓰지 않음)
- [ ] 외부 Google Sheets/Apps Script 백업·권한·워크북 및 동기화 복구 확인
- [ ] 복구 시간 목표(RTO), 데이터 손실 허용치(RPO), 연락·승인 체계 확정

**미확인 항목을 완료 처리하지 않는다.** DB의 `archive_mode=on` 같은 기술 설정은 실제 복원 가능한 백업의 증거가 아니다.
