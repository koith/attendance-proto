# Known Bugs / Regression Assets

반복 설명을 막기 위한 회귀 인덱스다. 상세 구현 역사는 HANDOFF 및 해당 QA를 따른다.

## 출퇴근
- 중복 출근: iOS 이중발화와 서버 동시 punch race가 원인이었던 이력. UI 잠금만 믿지 말고 서버 직렬화(advisory lock) 방어를 유지한다.
- 출근/퇴근 판정: 직전 이벤트는 시간 동률에 취약한 정렬 대신 검증된 최신 이벤트 판정 규칙을 유지한다.
- 실제 근무시간: 실서비스 raw 타각을 임의의 30분 단위로 반올림/절삭하지 않는다.
- 오버나이트/정정: 날짜 경계와 correction 적용이 세션 짝짓기를 깨지 않는지 관련 QA로 검증한다.

## UI / WebView
- 더블탭 확대 방지를 전역 touchend 핸들러로 구현하지 않는다. 과거 click 이중발화를 만들었다.
- 직원 카드 계열은 모바일 2열 및 데스크톱 확장 규칙을 깨지 않는지 확인한다.
- 직원 카드 직접 편집 연필 버튼은 사용하지 않는다. 근태 수정은 근무현황 경로를 사용한다.
- UI 수정은 모바일만 보고 끝내지 않고 데스크톱도 확인한다.

## 대타
- 폐기된 별도 대타근무 진입/우편함 UX를 되살리지 않는다.
- 대타 대상은 현재 확정된 출근 흐름에서 기록하며 자기 자신 및 선택 불가 상태를 기존 규칙대로 방어한다.

## 레시피 / 재고
- 단순 원재료를 직원용 제조 레시피 목록에 다시 노출하지 않는다. 제조가 필요한 베이스/반제품과 완성 제조 항목은 별도 정책을 따른다.
- 레시피 썸네일은 임의 이미지가 아니라 검증된 매칭만 사용하고 placeholder/null 잔여를 확인한다.
- 레시피와 재고는 데이터 의존성이 있으므로 한쪽의 분류/스키마 변경 시 다른 쪽 회귀도 확인한다.

## 급여
- 금액 최종값은 정수 KRW 원칙을 유지한다.
- 주휴·세율·휴게·야간수당의 법률/회계 정책을 검증 없이 임의 확정하지 않는다.
- 과거 Golden replay가 적용되는 계산 변경은 해당 회귀값을 유지하는지 확인한다.

## Google Sheets 리포트
- 열폭을 Google Sheets native auto-resize에만 맡기면 짧은 한글 헤더가 iPhone에서 18~20px까지 축소되어 글자가 잘리는 회귀가 발생한다. 각 동기화마다 해당 열의 실제 `getDisplayValues()` 전체를 측정해 가장 긴 표시 문자열이 온전히 들어가는 폭을 산출한다. 타입별 고정폭/bucket이나 임의 min/max는 사용하지 않는다.
- 디자인 서식값 read-back은 사람이 보는 결과의 Proof가 아니다. 실제 시트 화면/렌더 검증 없이 디자인 완료로 판정하지 않는다.
- 외부 사례를 참고했다고 보고하려면 실제 확인한 출처와 적용한 구조가 있어야 한다.
- iPhone Sheets에서 급여 결과/상태 열에 강한 배경색을 따로 칠하면 표 밖의 블록처럼 분리되어 보인다. 본문 배경은 연속성을 유지하고 결과는 글자 굵기/색, 헤더 대비, 세로 구분선, 숫자 우측정렬로 강조한다.\n- Apps Script workflow가 자격증명 누락 시 exit 0으로 배포를 건너뛰면 GitHub Actions 성공을 실제 배포 성공으로 오판한다. 배포 자격증명 누락은 실패 처리하며, 기존 월 시트의 동기화 시각/레이아웃/전체 그리드 잔존서식까지 확인해야 실제 반영으로 판정한다.\n- 보고서 폭이 줄어든 뒤 이전 버전이 사용영역 밖 열에 남긴 배경/서식은 현재 폭만 다시 칠해서는 사라지지 않는다. 월 재작성 시작 시 전체 시트 그리드의 내용/서식을 초기화한 뒤 현재 report width만 다시 작성한다.

- 새 월 탭 생성과 기존 월 자동갱신은 서로 다른 디자인 경로를 사용하면 안 된다. 둘 다 `_writeMonth` 단일 경로를 통과하고, 전체 그리드 초기화 → 공통 헤더/구분선/숫자서식 → 실제 내용 기준 auto-resize 순서를 유지하는지 `qa_sheet_new_month_format_contract.mjs`로 고정한다.


- 기준 월/시트를 다른 월에 "동일하게" 복제하는 작업에서 유사 디자인을 새로 만들어 적용한 뒤 성공으로 보고하면 안 된다. 기준 실제 화면과 대상 실제 화면의 헤더 대비, 섹션 서식, 셀 경계, 정렬, 열폭을 항목별로 비교한 Proof 없이는 동일성 완료 판정을 금지한다.
- 사용자가 차이를 발견한 뒤에야 불일치를 인정하는 패턴을 QA로 대체한다. 가능한 도구로 기준/대상을 직접 읽고 비교하며, 실제 렌더를 확인할 수 없으면 미검증/BLOCKED로 남긴다.


- Apps Script가 `width_source:'measured_display_text'`를 반환하는데 Supabase `sync-sheet`가 구형 `actual_cell_contents` 토큰만 허용하면 실제 Sheet 쓰기가 성공해도 Edge Function이 `SHEET_COLUMN_RESIZE_NOT_CONFIRMED`로 실패한다. 요청/응답 proof token은 `measured_display_text`로 단일화하고 `qa_sheet_auto_resize_contract.mjs`에서 양쪽 계약을 함께 고정한다.

- Sheet의 `마지막 동기화`/`마감시각`을 `Date.toISOString().slice(...)`로 만들면 UTC가 그대로 노출되어 한국 운영시각보다 9시간 느리게 보인다. 사람에게 보이는 Sheet 시각은 `Asia/Seoul`로 변환하고 `qa_sheet_edge_contract.mjs`로 고정한다.

## Sheet 날짜·시간 표시값
- Google Sheets의 날짜/시간은 내부적으로 serial number다. 서식을 잃으면 `46296`, `0.829166...`처럼 노출될 수 있다.
- 월 리포트 재작성 시 헤더 의미에 따라 날짜는 `yyyy-mm-dd`, 출퇴근/실근무/총근무/야간근무는 사람이 읽는 시간 형식을 다시 적용한다.
- 값 보존만 확인하지 말고 `formattedValue`도 검증한다. serial number가 화면에 노출되면 실패다.

## 운영 규칙
- 완료했다고 말하기 전에 실제 QA 증거를 만든다.
- 문서만 고친 내부 작업은 앱 버전을 올리지 않는다.
- 배포 작업 완료 보고에는 VERSIONING.md에 따른 실제 버전을 포함한다.

- Pages 배포 게이트가 부팅 문법/시작 smoke만 검사하면 다른 workflow의 보안·런타임·핵심 계약 회귀가 실패해도 운영 Pages가 배포될 수 있다. P0 게이트 자체에서 cross-domain adversarial/deep audit, runtime wiring, Sheet 핵심 계약을 직접 실행해 실패 시 build/deploy를 차단한다.
